Kong configuration and CORS
Configure Anthropic in Kong and fix permitted models and token limits server-side. The default sends OpenAI-style chat messages; native format works only when your route supports it. The response parser supports normalized chat completions and Anthropic text blocks.
Allow CORS from , including POST, OPTIONS, Content-Type, and Authorization or apikey as appropriate. Handle preflight requests before authentication rejects them.
For cookie sessions, allow credentials and use the exact origin, not a wildcard. Browser cross-site cookie restrictions may still apply. Protect the route with authentication, quotas, and rate limits. Never commit permanent secrets to GitHub.
